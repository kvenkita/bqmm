# Developer setup

This file documents the one-time steps needed to turn the hand-authored
scaffold into a compilable Stan package, plus the toolchain notes for this
machine. It is excluded from the built package via `.Rbuildignore`.

## 1. Toolchain (Windows)

Stan models are compiled to C++ at install time, so a matching Rtools is
required.

* This machine has **R 4.4.3** and **R 4.1.3** installed, but only **Rtools40**.
* R 4.4 officially pairs with **Rtools44** — using Rtools40 with R 4.4 is a
  common cause of Stan compile failures.

Choose one:

* **Recommended:** install Rtools44 from
  <https://cran.r-project.org/bin/windows/Rtools/rtools44/rtools44.html> and use
  R 4.4.3, **or**
* build under **R 4.1.3** (which matches the installed Rtools40).

Verify with:

```r
pkgbuild::has_build_tools(debug = TRUE)
```

### Windows "file too big" — required big-object flag

On Windows the Stan-generated object file exceeds the COFF object-format limit
and the assembler aborts with `Fatal error: ... file too big`. Fix it with the
big-object assembler flag, supplied through a **user-level Makevars** (the
package's own `src/Makevars.win` is regenerated by `rstan_config()` at install,
so a flag added there does not survive). `tools/Makevars.win` in this repo
contains:

```
CXX17FLAGS += -Wa,-mbig-obj
CXX14FLAGS += -Wa,-mbig-obj
CXXFLAGS   += -Wa,-mbig-obj
```

Apply it for a build by pointing `R_MAKEVARS_USER` at that file, then install
with a direct `R CMD INSTALL` (which honours `R_MAKEVARS_USER`, unlike
`pkgbuild::compile_dll`, which overrides it):

```sh
R_MAKEVARS_USER=tools/Makevars.win \
  R CMD INSTALL --no-multiarch .
```

Or copy `tools/Makevars.win` to `~/.R/Makevars.win` once, machine-wide.

## 2. Install dependencies

```r
install.packages(c(
  "rstan", "rstantools", "StanHeaders", "posterior",
  "RcppParallel", "BH", "RcppEigen",
  "bayesplot", "lqmm", "nlme", "SBC", "testthat", "knitr", "rmarkdown"
))
```

`lme4`, `Rcpp`, `devtools`, `roxygen2` are already installed.

## 3. Wire up the compiled model

The scaffold ships the Stan sources in `inst/stan/` and all pure-R logic, but
**not** the generated glue that `rstantools` produces (`R/stanmodels.R`,
`src/Makevars*`, `src/stanExports_*`, `configure`/`configure.win`). Generate it
in place:

```r
# from the directory *containing* the bqmm/ folder
rstantools::rstan_create_package(
  path     = "bqmm",
  stan_files = character(0),   # we already placed files in inst/stan
  roxygen  = FALSE,
  travis   = FALSE
)
```

If `rstan_create_package()` refuses to populate a non-empty directory, run it
against a temporary path and copy the generated `configure`, `configure.win`,
`src/Makevars`, `src/Makevars.win`, `R/stanmodels.R`, and
`inst/include/stan_meta_header.hpp` into this package, then add

```r
#' @useDynLib bqmm, .registration = TRUE
#' @importFrom Rcpp sourceCpp
```

to `R/bqmm-package.R` (the commented lines in `NAMESPACE` already note this).

## 4. Build documentation and compile

```r
devtools::document()   # regenerates NAMESPACE + man/ from roxygen
devtools::load_all()   # compiles inst/stan/bqmm.stan -> stanmodels$bqmm
devtools::test()
```

## 5. Sanity run

```r
fit <- bqmm(distance ~ age + (1 | Subject),
            data = nlme::Orthodont, tau = c(0.1, 0.5, 0.9),
            chains = 2, iter = 1000, seed = 1)
summary(fit)
```

Expect Rhat < 1.01, no divergent transitions, and adjusted vs. unadjusted
`vcov()` intervals that differ in width.
